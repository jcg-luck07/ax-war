# 실행 방법

## 준비 (한 번만)

1. Node.js 20 이상, Docker Desktop 설치. Docker Desktop 을 켜 둔다 (로그인 불필요).
2. 프로젝트 폴더에서:

```bash
npm install
npm run setup
npm run db:up
```

3. `.env.local` 의 `DATABASE_URL=` 줄 주석(`#`)을 지운다 (이미 지워져 있으면 생략).
4. 원본 CSV 를 DB 로 복사한다 (원본 파일은 읽기만 한다):

```bash
node scripts/ingest.mjs
```

## 실행

```bash
npm run db:up
```

```bash
npm run dev
```

http://localhost:3000

## 로컬에서 누구로 쓰나

로컬에는 axhub 로그인이 없어서 `.env.local` 의 값으로 사용자가 정해진다 (없으면 모든 역할 + 관리자).

```
DEV_USER_NAME=홍길동
DEV_USER_ROLES=finance            # 쉼표로 여러 개, all 이면 전부
DEV_USER_ADMIN=0                  # 1 이면 관리자
```

역할 6개: `marketing_member`(마케팅 팀원) `marketing_team`(마케팅 팀장) `finance`(재무팀) `contract_mgr`(계약 담당) `masil_ceo`(Masil 대표) `ceo_board`(CEO/이사회). 로컬에서는 오른쪽 위 "시험 계정"으로 바꿔 볼 수 있다(배포본에는 없음).
배포본에서는 관리자가 **사용자·권한** 화면에서 이메일별로 역할을 등록한다.

## 처음 써 보는 순서

1. **안건 접수 → 안건 제출** (팀원): 안건 종류(인플루언서 계약 / 캠페인 집행) → ID·지급 예정일·계약 체결 기한·요청금액·메모, 첨부서류, 공헌이익 계산 칸을 모두 채워 팀장에게 보고. **안건 접수** (팀장): 첨부서류·공헌이익을 보고 체크리스트 항목을 모두 확인해야 접수 버튼이 켜진다.
2. **안건** → 혜인 전속계약 → 위쪽 **업무 흐름** 그림에서 지금 어디서 기다리는지 확인.
3. **다음 행동**에서 승인(권한이 있으면) → 후속 작업이 생기고 그림이 바뀐다 → 안건 화면 아래에서 작업을 완료 처리.
4. **조건이 바뀌었나요?** 에 고정 피 `20`, 이어서 `8` 을 넣어 승인권자가 어떻게 바뀌는지 본다.
5. **할 일** 에서 재무 역할로 같은 질문(300억 연결 여부) 일괄 회신, 구간 안 기안에는 집행일 조정 회신.
6. **업무 흐름** 에서 단계마다 기다리는 안건 수, **데이터 모델** 에서 지표 정의, **현금 재전망** 에서 하회 구간.

## 원본 자료로만 채우기

로컬 DB 의 안건을 모두 지우고 원본 자료에서 나온 안건만 적재한다 (확대 기안 25건 + 혜인 전속계약 통보 1건). 원본 복사본과 원본 파일은 그대로다.

```bash
node --import ./scripts/_register.mjs scripts/seed-original.mjs
```

## 합성데이터로 써 보기

원본과 따로 만든 가상 안건(확대 기안 18, 전속계약 10, 접수 대기 3)이 `합성데이터/` 에 있다. 자세한 설명은 `합성데이터/README.md`.

```bash
node --import ./scripts/_register.mjs scripts/seed-synthetic.mjs
```

지우기는 같은 명령에 `--clear`. (아래 자동 시험은 안건을 모두 지우므로 시험 뒤에 다시 적재한다.)

```bash
node scripts/test-rules.mjs

node --import ./scripts/_register.mjs scripts/test-metrics.mjs
node --import ./scripts/_register.mjs scripts/test-cash.mjs
node --import ./scripts/_register.mjs scripts/test-engine.mjs
node --import ./scripts/_register.mjs scripts/test-w02.mjs
node --import ./scripts/_register.mjs scripts/test-submissions.mjs
node --import ./scripts/_register.mjs scripts/test-app.mjs
```

> engine·w02·app·submissions 시험은 로컬 DB 의 안건·이력·승인·작업을 지우고 시작한다 (원본 복사본은 유지).

## 제약

- 배포본 DB 에는 원본 데이터가 없다 (배포 시 적재 방법 결정 필요).
- 배포본에서는 axhub 로그인한 사람만 상태를 바꿀 수 있고, 역할이 없으면 볼 수만 있다.
- 상대방 통보·발주 전달은 프로그램이 대신 보내지 않는다 (작업으로 만들어 사람이 처리하고 완료 표시한다).

## 시험은 별도 DB(`app_test`)를 써요

시험(`scripts/test-*.mjs`)은 안건을 모두 지우고 시작해서, 쓰던 DB(`app`)가 아닌 `app_test` 에서 돌려요 (`scripts/_register.mjs` 가 자동으로 바꿔요). 안건 초기화 함수는 이름이 `_test` 로 끝나는 DB 에서만 동작해요.

처음 한 번만:

```bash
npm run db:test-setup
DATABASE_URL=postgres://postgres:postgres@localhost:5432/app_test node scripts/ingest.mjs
```
