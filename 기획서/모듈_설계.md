## 3. 모듈 사이 약속 (코드로 지켜지는 것)

- **엔진은 업무를 모른다.** `engine.ts`에 업무 이름이 없음을 test-w01이 검사한다.
- **규칙은 코드가 아니라 데이터.** `authority.rules.ts`의 표만 고치면 판정이 바뀐다.
- **권한을 넘는 결정은 거부.** 더 낮은 권한이 결정하면 `EngineError`.
- **모르는 사실은 확정하지 않고 확인 요청.** 참이 되면 권한이 더 높아질 때만 묻는다.
- **원본과 가정을 섞지 않는다.** 모든 안건·작업·회신에 `data_origin`.
- **이력은 추가만.** `case_events`.
- **AI·LLM은 쓰지 않는다.** 계산·판정·요약 모두 코드가 한다.
- **배포본 보호.** 배포본(production)에서는 로그인한 사람만 상태를 바꾼다.

## 4. DB 기본 구조

| 테이블 | 담는 것 |
|---|---|
| `decision_cases` | 안건(유형, 상태, 마감일, 연결 대상 번호, 승인권자, 데이터 성격) |
| `case_events` | 이력(추가만) |
| `approvals` | 승인 요청과 결과(대체됨 포함) |
| `tasks` | 후속 작업, 확인 요청과 회신 |
| `assumptions` | 가정값·모의 입력 (테이블만 있고 아직 화면에서 쓰지 않음) |
| `source_rows` / `source_files` | 원본 CSV 행 복사본과 파일 대장(해시) |

## 5. 아직 하지 않았거나 한계인 것

- **배포본의 DB에는 원본 데이터가 없다.** 배포하려면 `axhub.yaml`의 DB를 켜고, 필요한 CSV를 저장소에 복사본으로 넣어 적재하는 방법을 정해야 한다(02_masil은 2.1MB).
- `assumptions` 테이블은 지표 가정을 화면에서 저장하는 데 쓰려고 만들었지만, 지금은 URL 값으로만 가정을 바꾼다.
- 현금 재전망은 이미 확정된 스케줄만 합산한다. 공식 전망과 40~50억 원 차이가 나는 원인은 확정하지 못했다.
- 시연 영상, 설계 설명 문항 작성은 아직 하지 않았다.
