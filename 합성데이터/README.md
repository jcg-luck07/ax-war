# 합성데이터

시험용으로 **새로 만든 가상 데이터**예요. 원본 데이터(`01_참가자_배포용/04_원본데이터/`)는 읽기만 하고 한 글자도 고치지 않았어요.
(A05 6장: 합성 관측값은 원본 사실과 구분해 표시하고, 추가 행에는 식별자·적용 시점·원본 연결·생성 이유를 남긴다.)

## 파일

| 파일 | 내용 | 건수 |
|---|---|---|
| `syn_expansion_plans.csv` | 캠페인 확대 기안 (원본 `mkt_budget_plan_ms.csv` 와 같은 모양에 사실 열을 더함) | 18 |
| `syn_contract_notices.csv` | 인플루언서 전속계약 갱신 통보 | 10 |
| `syn_submissions.csv` | 팀원이 올렸지만 팀장이 아직 접수하지 않은 안건 (접수 대기) | 3 |

구분자는 원본과 같은 `|` 예요. 모든 행에 아래 열이 있어요.

- `syn_id` 합성 식별자 (`SYN-E…` 확대 기안, `SYN-C…` 계약, `SYN-S…` 접수 대기)
- `applies_at` 적용 시점 — 가상기업 기준일 2026-07-01
- `source_link` 원본 연결 — 어느 원본 행(캠페인·인플루언서)에 기대어 만들었는지
- `reason` 만든 이유, `scenario` 이 행이 시험하는 상황과 기대 결과

캠페인·인플루언서 ID 는 모두 원본 마스터(`m_campaign_ms.csv`, `m_influencer_ms.csv`)에 있는 것만 썼어요. 금액·날짜는 지어낸 값이라 **실제 계약·실제 성과가 아니에요**. 앱에서는 데이터 성격이 "합성"으로, 제목 앞에 `[합성]`이 붙어요.

## 어떤 상황을 담았나

**확대 기안 (E01~E18)**: 소액 전결 / 하회 구간 안(7/21~8/21) 소액 / 구간 경계(직전·첫날·마지막날·직후) / 건당 한도 초과 / 정확히 1천만 원 / 기안 총액 1억 초과 / 300억 연결 / 300억 연결 모름 / 집행일 모름 / 마감 지남·임박·먼 건 / 공헌이익 최하위 vs 1위 인플루언서의 큰 금액.

**전속계약 (C01~C10)**: 연 28억 / 8억 / 정확히 10억 / 10억+1천만 / 하회 구간 안 지급 / 지급일 모름 / 통보 기한 지남 / 3일 전 / 4주 밖 / 300억 연결.

**접수 대기 (S01~S03)**: 팀장 접수를 기다리는 보고 (공헌이익 양수 / 음수 / 마감 5일 + 구간 안). 첨부서류는 `첨부문서/` 의 예시 문서가 붙어요.

## 첨부 예시 문서 (`첨부문서/`)

접수 대기 3건(S01~S03)에 붙는 가상 서류예요. 안건 접수 화면에서 팀장이 열어 볼 수 있어요. 모든 문서 맨 위에 `[합성 데이터]` 표시가 있고, 원본에서 가져온 수치는 "원본 계산값", 지어낸 값은 "추정"으로 구분해 적었어요.

| 폴더 | 안건 | 서류 |
|---|---|---|
| `SYN-S01/` | 토모카 기초 캠페인3 집행 6,500,000원 (공헌이익 +35,800,000원) | 기안서, 추계서(csv), 직접 추가: 판단 근거 자료 |
| `SYN-S02/` | 토모카 전속계약 갱신 연 700,000,000원 (공헌이익 −424,000,000원) | 기안서, 추계서(csv), 계약서 발췌, 직접 추가: 판단 근거 자료·상대방과 오간 메일 |
| `SYN-S03/` | 코코라운지 기초 캠페인2 집행 15,000,000원, 마감 5일 (공헌이익 +77,400,000원) | 기안서, 추계서(csv), 직접 추가: 판단 근거 자료 |

추계서의 숫자(원 단위, 1원까지)는 제출 화면의 공헌이익 칸에 입력한 값(`syn_submissions.csv`)과 같아요. 파일 이름의 앞부분으로 첨부 종류가 정해져요 (기안서·비용및성과추계서·계약서는 고정 칸, 판단근거자료·상대방_메일은 "직접 추가" 첨부로 종류 이름을 붙여서 올려요). 예시 문서를 다른 안건 제출 때 직접 올려 봐도 돼요.

## 쓰는 법 (로컬 DB)

```bash
node --import ./scripts/_register.mjs scripts/seed-synthetic.mjs
```

접수 대기까지 함께 적재하고, 이미 있는 합성 안건은 건너뛰어요 (몇 번 돌려도 중복 없음). 지우려면:

```bash
node --import ./scripts/_register.mjs scripts/seed-synthetic.mjs --clear
```

합성 안건과 `[합성]` 접수 대기만 지우고, 원본 복사본과 사람이 만든 안건은 그대로예요.

## 시험하면서 알게 된 것

- 역할은 6개(마케팅 팀원·마케팅 팀장·재무팀·계약 담당·Masil 대표·CEO/이사회)라서, 원문의 "그룹 CEO 승인"은 CEO/이사회로 통합해 판정해요(해석 가정). `SYN-E12`(구간 안 + 300억 연결)처럼 두 규칙이 같이 걸려도 결론은 같아요.
- `SYN-C01`·`SYN-C07` 처럼 10억을 넘는 계약은 지급일을 몰라도 승인권자가 바로 확정돼요. 모르는 사실이 더 높은 권한을 만들 수 없기 때문이에요.
